# 原衣原身、PBZ 蒙皮与物理

## 对齐与导出小样

1. Blender 导入同体型的原衣、躯干、手脚和 PBZ 原生参考网格。按原 NIF 核对 shape 和贴图，并保存原始正侧视对照。保留烘焙前的 UV 和皮肤，逐个切换衣层检查肩颈、手腕、脚踝和露肤区域。原 NIF 裁去的皮肤从同一体型和预设的完整原身补齐。
2. 对原衣原身共同应用朝向、均匀缩放和平移。先以肩、肘、腕、髋、膝、踝及靴底记录对位差，再局部修形。肩到腕分段渐变，贴身衣物与皮肤共用过渡。硬质甲片和靴饰按连通块、依骨链尽量刚性对位，保留原轮廓。需要去黑色打底之类的款式时，用部件及裙、袖、靴的实际几何来分组，核对切换是否误删应保留的面。
3. 先导出一个缩小范围的蒙皮小样。FBX 只选 Armature 与蒙皮网格，参考姿势导出，关闭 Add Leaf Bones 和动画烘焙，保留原动画要求的公共骨。UE 导入为 Skeletal Mesh，核对使用兼容骨架或按参考骨架保留私有骨架。逐级比较轴向、单位、根比例、参考变换及骨层级。厘米和米只转换一次。用同一动作的头、手、脚坐标确认结果，再将验证过的配方用于全套。

## 权重、UV 和部件

- 将源权重按实际骨链映射到 PBZ 公共骨。同名骨的父级和局部参考变换与目标原生数据一致。用同侧、同解剖区域的最近面插值转移贴身层权重，并按距离渐变。用连通块及真实关节活动处理硬件，避免躯干串到近邻上臂、腕口串到对侧。导出前查缺权重、未归一、每点 influence 上限、断链与越界索引。
- 用 PBZ 待机、跑停、蹲起、跳跃、持械和攻击检查穿模。问题只在动作中出现时取对应姿势及皮肤变形后的顶点，检查腋下、肘、胯、膝、腕、靴口。用户重新修形后，对实际修改网格重做权重及动作抽查。
- Join 之前按语义统一主 UV 层名称。NIF 的 `UVMap` 与 PBZ 的 `UV0` 同时存在时先保留副本，再核对逐面循环坐标。导出和重导入后复查 UV0、材质槽的实际排序、每个 LOD 的 section、网格 bounds 和可显隐区域。
- 维护「源部件 → Blender 材质槽 → UE 材质索引与 LOD section → 换装组」映射。皮肤、靴面、装饰和可隐藏底衣需要独立控制时提前拆槽。删除或移动的附件要与最终 LOD 核对。

## 选择物理路线

先用原生日常动画跑通主体。一个 Body 网格能解决时评估直接挂载。需要私有动画图的多组件方案时，从真正被评估的主网格用 `Copy Pose From Mesh` 复制公共骨姿势，再在私有 AnimBP 里运行局部节点。检查主从求值顺序、组件空间、Leader Pose 及切换后重绑。[框架组件映射](outfit-framework.md)

胸臀等辅助骨由私有 RigidBody 节点推算时，受影响的皮肤、贴身层与甲片共用运动来源。刚性部件限制不需要的摆动。披风或飘带可以用当前 UE 支持的 Chaos cloth 或辅助骨约束。HDT-SMP XML 和原 Skyrim 布骨可参考运动范围。按 PBZ 实际肢体测定固定点、Max Distance、刚体约束和碰撞代理，并检查跑停回稳、穿模及性能。

多材质附件跟随同一物理布网格时，先检查标准 Cloth Bind 是否支持目标 LOD 与 section 布局。需要自写 UE 编辑器扩展时，持久写入渲染 section 的 cloth mapping、资产 GUID、LOD 绑定和对应源 `UserSectionsData`，按引擎版本核对 BoneMap 与 RequiredBones 等。保存重开后再检查 Cook 结果和真实动作。对于只在游戏里出现的脚底下陷，走[靴底定位](runtime.md#靴底定位)。
